═══ 01_DRAFT ═══

Cyera Research has discovered a critical vulnerability, tracked as CVE-2026-6471, in PostgreSQL versions 9.4 through 18.2. The flaw exists in the database replication protocol and allows low-privilege accounts with the REPLICATION attribute to bypass security systems, load arbitrary code onto the server, and achieve remote code execution across Windows, Linux, and macOS. The vulnerability stems from an unvalidated plugin-loading path used during logical replication that was never subjected to the security restrictions applied to standard SQL plugin loading. 

An attacker can exploit this foothold to escalate privileges to full PostgreSQL superuser, install persistent backdoors, modify system catalogs directly, and execute operating system commands. The vulnerability has been present since 2014, and a threat hunt across VirusTotal identified 114 malicious PostgreSQL plugins already in the wild. PostgreSQL acknowledged the report on February 27, 2026, after it was submitted on February 21, 2026, and officially published a security release fixing the issue on August 22, 2026. 

To mitigate the risk, administrators must apply the security update, audit all REPLICATION accounts, block outbound SMB port 445 and NFS port 2049 from database servers at the firewall, and review pg_hba.conf configurations for overly permissive rules.
