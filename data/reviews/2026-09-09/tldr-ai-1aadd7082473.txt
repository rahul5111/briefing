═══ 01_DRAFT ═══

Today, Cohere presents a serving engine for North Mini Code built around a decode megakernel. Using BF16 on a single H100, the system achieves 292 tokens per second at batch size 1, or 62% of Speed-of-Light bandwidth, making it 1.58 times faster than vLLM. Across end-to-end benchmarks, it runs 1.25 to 1.41 times faster than vLLM while supporting continuous batching, paged attention, ragged sequence lengths, and an OpenAI-compatible endpoint with tool calling.

North Mini Code is a 30-billion parameter model with 3.3 billion active parameters per token. In BF16, this requires streaming 6.6 gigabytes of weights per decode step, plus approximately 0.5 gigabytes of KV cache at an 8K context. An H100 delivers 3.35 terabytes per second of High Bandwidth Memory, putting the theoretical Speed-of-Light at about 470 tokens per second. Standard stacks like vLLM serve this model at 185 tokens per second, utilizing 39% of Speed-of-Light. 

The performance gap exists because autoregressive decoding is memory-bound rather than compute-bound, and traditional serving stacks launch hundreds of small kernels sequentially, leaving streaming multiprocessors waiting during the gaps. The megakernel solves this by running the entire forward pass as a single persistent kernel launched across streaming multiprocessors, using a task interpreter pattern, global memory counters for fine-grained synchronization, and weight prefetching that streams immutable weights from HBM before activation dependencies are resolved.
