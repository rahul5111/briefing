1. Funes is a durable local memory layer for coding agents that indexes session traces automatically.
2. Funes supports coding agents including Claude Code, Codex, pi, and Hermes with a single binary.
3. Funes works locally on your machine and indexes each completed turn incrementally without ML runtime dependencies.
4. Funes can publish memory to a private Hugging Face dataset so your memory follows you across machines.

═══ 01_DRAFT ═══

A new open-source tool called funes provides a durable, local memory layer for coding agents including Claude Code, Codex, pi, and Hermes. Available as a single binary from github.com/huggingface/funes, the software indexes session logs directly from a user machine using incremental runs, combining vector and BM25 search with a cross-encoder and local Lance dataset. 

The system allows agents to recall exact raw text evidence rather than summaries, complete with agent name, timestamp, session, and turn provenance. Users can install the integration via a single command such as funes add claude, which builds the initial index and installs automation for completed turns. 

Memory can also be synchronized across machines and shared with teams by binding a Hugging Face dataset, for example using funes add codex acme/funes-memory. The software includes built-in credential redaction to scan and withhold secrets before publishing to the Hub. Additionally, the standalone command funes ask allows users to query memories directly without altering persistent agent setups. 

In benchmark testing against agent compaction and written handoffs on tasks requiring prior session knowledge, funes recall avoided the flattening failures of compaction and proved to be four to eight times cheaper than a written handoff. Embedding, reranking, and inference backends run locally on the user machine with no required ML runtime dependencies or separate API rental accounts.
