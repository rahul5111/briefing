═══ 01_DRAFT ═══

Zod 4.5 introduces a method memoization pattern that reduces the heap memory footprint of a bare string schema from 7.5 kilobytes in version 4.4 down to 784 bytes. By default, Zod classes define methods as getters on a standard prototype. The first time a method is accessed on an instance, the getter returns a bound implementation and assigns it as an own property to that instance, memoizing it permanently while avoiding getter-invocation overhead on subsequent accesses. Instance methods that are never used are never materialized or stored as own properties. This change addresses V8 memory allocation behavior, where objects with 21 or more own properties trigger a 1616-byte backing store. A regular string schema in Zod 4.4 carried 49 own properties, forcing every instance into that largest backing store tier. Under the new system in Zod 4.5, there are only six eagerly bound properties which are underscore zod, def, type, format, minLength, and maxLength, with all other methods residing on the memoizing prototype.
