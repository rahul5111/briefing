═══ 01_DRAFT ═══

Security researchers at Huntress have uncovered a series of attacks deploying rogue ScreenConnect remote access installations across unrelated endpoints to execute multi-stage VBScript chains. The incidents, observed in late August, began with social engineering tactics such as fake tech-support scams using Windows Quick Assist, phishing via Microsoft Edge downloads, and deceptive Geek Squad refund searches. 

Once initiated, the rogue ScreenConnect clients spawned Windows Script Host child processes to execute four sequential VBScript files named 1.vbs through 4.vbs. The first script profiles the host system, checking for existing ScreenConnect installations, enumerating security software such as Microsoft Defender and CrowdStrike, and verifying that system RAM exceeds five gigabytes. The subsequent scripts coordinate with a Dropbox URL to download, decode, and decrypt secondary payloads using AES-CBC and single-byte XOR routines. Depending on the host's environmental profile, the campaign delivers user-level ScreenConnect backdoors, privilege escalation tooling, or cryptocurrency miners and tunneling utilities. 

Attackers established persistence across the victims' machines by creating a WindowsServiceHost user registry run key pointing to a VBScript file inside the user AppData directory. Operations were further supplemented by auxiliary remote monitoring and management tools, including UltraViewer. Huntress stopped the affected sessions before malicious execution could fully progress. Meanwhile, ConnectWise published an advisory on September 3, 2026, warning of an issue impacting file transfer behavior in ScreenConnect sessions and advising partners to temporarily disable file transfer permissions until an official Common Vulnerabilities and Exposures fix is released within the week.
