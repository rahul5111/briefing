═══ 01_DRAFT ═══

A sharded Postgres database system called Neki processes queries across multiple servers by replicating the Postgres authentication system, wire protocol, and parser while utilizing a shard-aware distributed query planner. 

When an application sends a query, the Neki router handles the complete Postgres authentication exchange, including SCRAM-SHA-256, entirely in Go. The router supports both the simple query protocol, which sends the entire SQL statement in a single message, and the extended protocol, which separates communication into Parse, Bind, Describe, Execute, and Sync phases. 

The router then converts the query text into an abstract syntax tree using a parser built in approximately 18,000 lines of Go. If no cached plan is available, this syntax tree is passed to the distributed query planner. 

To execute queries across the infrastructure, the planner relies on the database schema from an authoritative shard and data topology stored centrally in etcd and cached on every router node. In a deployment with two tables spread across four shards using primary keys as shard keys, tables are distributed by taking an id, computing a hash using a deterministic xxhash function, and assigning it to a shard based on specific ranges. Because customer rows and their corresponding orders may reside on different shards, the planner creates Route plan nodes to execute scatter-gather queries across the necessary nodes and joins the matching results within the router.
