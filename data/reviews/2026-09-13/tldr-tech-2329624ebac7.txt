═══ 01_DRAFT ═══

An experienced developer managing an AI-driven software factory shared a workflow breakdown involving a real factory run from the previous week. The run featured seven tasks, 90,000 lines of code changes, and fifteen hours of agent work with two human actions to start the process and review before final deployment. The operation involved 91 unique agents working in parallel. 

The system relies on a control layer where agents connect by messages and actions, split into two primary loops. The first loop handles planning and creating specs, while the second manages execution and creating code. The planning loop averages one million tokens per issue, compared to 0.5 million tokens for the build loop. 

The workflow is guided by four main principles. First, developers must be explicit about where to bottleneck the system, controlling human involvement by focusing attention on narrower choke-points like pull requests rather than reviewing every line of code. Second, developers must not write any lines of code; when output is unsatisfactory, the machine is fixed rather than the code. Third, validation is shifted left toward ideation and planning. Fourth, deterministic code and static analysis scripts are enforced over prose and LLMs wherever possible, including dead code removal, complexity caps, and strict type systems. 

The planning loop utilizes Claude Code's native Plan mode and a github-issue-create skill to establish original user intent, acceptance criteria, and specific validation steps across unit tests, end-to-end tests, local browser testing, and post-deploy production testing.
