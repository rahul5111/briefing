═══ 00_KEY_POINTS ═══

1. Before rendering a report or dashboard artifact, call validate_artifact with the complete manifest and bounded snapshot.
2. Artifact snapshots must be bounded to at most 50 datasets, 2,000 rows per dataset, and 3MB total payload.
3. When mode equals work_mode is positively identified, do not call render_artifact, render_chart, or render_table.
4. Publish validated artifacts through Sites when the full Sites building and hosting lifecycle is callable.
5. Default every chart title to a neutral, descriptive label that identifies what is plotted or time scope.
6. Treat by dimension in a chart title, subtitle, or visible header as an encoding contract.

═══ 01_DRAFT ═══

Before rendering any report or dashboard artifact, the system requires calling validate_artifact with a complete manifest and a bounded snapshot. Failed render attempts must not be used as an iterative validator because they can create visible placeholder cards. Artifact snapshots are strictly limited to at most 50 datasets, 2,000 rows per dataset, a 3MB total payload, and 200,000 total inline source characters. 

When work mode is positively identified, tools such as render_artifact, render_chart, or render_table must not be called to deliver visuals or reports, as the trusted work mode rendering path may drop standalone plugin widgets lacking an appContext. For durable reports or dashboards in work mode, the validated artifact should be published through Sites when the hosting lifecycle is callable, with HTML serving as the automatic fallback. 

Native artifact charts require encodings.x.field and encodings.y.field or encodings.y.fields, alongside an optional encodings.color.field for grouped tidy data, while legacy manifest fields like xField and series are automatically rejected. Native artifact tables must include a defaultSort with a declared column field and an asc or desc direction. When a validated Model Context Protocol artifact requires a hosted Sites link, the system calls export_artifact_package and deploys that package instead of hand-rolling standalone HTML. 

The render_chart tool is used to render a compact Data Analytics chart from already-reviewed provenance and table data. Chart titles should default to a neutral, descriptive label identifying what is plotted, such as the metric, comparison, dimension, or time scope, avoiding inferred narrative takeaways unless explicitly requested. Subtitles should instead provide a reader-facing insight or takeaway not already covered by the title. Furthermore, any mention of by dimension in a visible chart title, subtitle, or header acts as an encoding contract that must be visibly encoded on an axis or through color, grouping, stacking, or faceting.
