═══ 01_DRAFT ═══

Manifold Security disclosed eight security flaws across seven command-line AI coding agents where a repository's Git configuration names a command that the agent executes on the developer's machine. The vulnerability relies on core.fsmonitor, a Git performance setting read from the repository's .git/config, which agents call in the background during session startup to check changed files. The command runs as the user, outside the agent's sandbox, and without an approval prompt when a repository arrives with its .git directory intact via shared archives, drives, sync folders, or USB sticks. 

Fixes have shipped for goose, Cursor, and OpenAI's Codex. Goose versions prior to 1.44.0 are affected, with a fix in 1.44.0. Codex CLI is fixed in 0.131.0, Codex Desktop for macOS in 26.519.22136, and Codex Desktop for Windows in 26.519.21041. OpenAI published three CVEs covering Codex, including CVE-2026-19592, with OpenAI stating that the helper runs outside the command sandbox and without a user-approval prompt, allowing attacker-controlled code to run with user privileges to read, change, or delete files. GitHub assigned CVE-2026-72718 to goose with a CVSS 4.0 base score of 7.0.

Hermes Agent, Qwen Code, Grok Build, and a second path in Claude Code remained unpatched during retesting on September 1. Claude Code version 2.1.196 fixed the core.fsmonitor path, but the claude ultrareview path was confirmed live on version 2.1.252. Qwen Code versions 0.19.6 and 0.22.3, Hermes Agent versions 0.18.2 and 0.21.0, and Grok Build versions 0.2.93 and 1.0.13 were also confirmed affected. On Claude Code and Hermes Agent, the payload fires before the workspace-trust prompt; on Qwen Code, before authentication; and on Grok Build, on the first keystroke. No exploitation of these findings has been reported in the wild.
